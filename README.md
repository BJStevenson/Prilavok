## Описание проекта

**Бизнес-задача** — 

Эффективность дарксторов компании «Прилавок» критически зависит от точности управления запасами. Текущая система планирования закупок работает на субъективных оценках аналитиков, что приводит к повышенной недополученной выручке или прямым убыткам.

Необходимо разработать автоматизированную систему прогнозирования недельных продаж для каждого отдела во всех дарксторах.

**Цель** — построить модель машинного обучения, которая минимизирует ошибку прогноза на плановых данных.

**Подход** — градиентный бустинг (CatBoost) с временными признаками и лаговыми переменными.

## Описание данных

Для работы доступны исторические данные о продажах за февраль 2023 — октябрь 2025, организованные в виде нескольких таблиц в PostgreSQL:

Таблица sales — исторические данные о продажах:

Store — номер даркстора (1–45).
Dept — номер отдела внутри даркстора (1–99).
Date — неделя (дата начала недели).
Weekly_Sales — недельные продажи (руб., целевая переменная).
IsHoliday — признак праздничной недели.
Таблица stores — информация о дарксторах:

Store — номер даркстора.
Type — тип даркстора (A, B, C).
Size — размер даркстора в условных единицах.
Таблица features — внешние факторы:

Store, Date — идентификаторы.
Temperature — средняя температура за неделю.
Fuel_Price — средняя цена бензина.
MarkDown1-5 — факторы рекламных акций и скидок.
CPI — индекс потребительских цен.
Unemployment — уровень безработицы.
Таблица plan — данные для инференса (ноябрь 2025 — июль 2026), содержит те же столбцы, что и sales, кроме Weekly_Sales.

**Исторический период:** 2023-02-05 — 2025-10-26
**Плановый период:** 2025-11-02 — 2026-07-26

## Описание использованных и созданных признаков, участвующих в модели

* Исходные признаки (из таблиц):

    * store — идентификатор даркстора
    * dept — идентификатор отдела
    * type — тип магазина (A, B, C)
    * size — площадь магазина
    * is_holiday — флаг праздничной недели
    * temperature — температура (изначально в F, конвертирована в C)
    * fuel_price — цена топлива
    * cpi — индекс потребительских цен
    * unemployment — уровень безработицы
    * factor1,2,3,4,5 — синтетические макроэкономические факторы

* Временные признаки (созданы из date):

    * year — год
    * month — месяц (1–12)
    * week — номер недели (1–52)
    * quarter — квартал (1–4)
    * season — сезон (Зима, Весна, Лето, Осень) — маппинг месяцев

* Лаговые признаки (по каждому store + dept):

    * sales_1week_ago — продажи неделю назад (shift(1))
    * sales_2week_ago — продажи 2 недели назад (shift(2))
    * sales_4week_ago — продажи 4 недели назад (shift(4))

* Скользящие средние (по каждому store + dept):

    * mean_sales_2week — среднее продаж за последние 2 недели (без учёта текущей)
    * mean_sales_4week — среднее продаж за последние 4 недели (без учёта текущей)

* Кумулятивные признаки:

    * avg_sales_before — средние продажи с начала истории до предыдущей недели (expanding().mean().shift(1))
    * Удалённые признаки (PSI ≥ 0.2):
    * year, fuel_price, cpi, quarter, unemployment, factor1

## Логика обучения

**Модель:** CatBoostRegressor

**Гиперпараметры:**
- iterations: 500
- learning_rate: 0.05
- depth: 6
- random_seed: 42

**Категориальные признаки:** `['store', 'dept', 'is_holiday', 'type', 'date']`

**Метрики качества:**
- MAE: 1913 руб
- RMSE: 3741 руб
- R2: 0.97

**PSI-анализ:** удалены нестабильные признаки с PSI ≥ 0.2: `['year', 'fuel_price', 'cpi', 'quarter', 'unemployment', 'factor1']`

**Переобучение отсутствует** (MAE на валидации лучше, чем на обучении)

## Архитектура пайплайна

**DAG:** `prilavok_batch_inference` (запуск каждое воскресенье в 20:00)

**Задачи:**
1. `load_data` — объединение таблиц plan, sales, stores, features во временную таблицу
2. `preprocess_features` — предобработка, создание признаков, фильтрация строк плана
3. `load_model` — загрузка модели CatBoost из S3 (Yandex Cloud)
4. `run_inference` — получение предсказаний
5. `save_predictions` — запись в таблицу predictions

**Источники данных:** PostgreSQL (connections: postgres_default)

**Артефакты:** Модель хранится в S3 (bucket: S3_BUCKET (из Airflow vars) `s3-ds-20260421-d53f8171a0`, 
model key: `prilavok_sales_predictor.pkl`)
